# flexiweather

FlexiWeather is a premium Flutter weather companion for Android and iOS. It pairs a calm, dark Material 3 interface with live forecasts from the free Open-Meteo APIs.

## Features

- Current conditions, feels-like temperature, humidity, wind, UV index, visibility, sunrise, and sunset
- Worldwide city search using Open-Meteo Geocoding
- Current-location weather with permission-aware location handling
- 24-hour hourly outlook with precipitation probability and a seven-day forecast
- Celsius and Fahrenheit display, with the preference saved locally
- Favorite cities saved on device
- Weather-aware animated background gradients
- Loading, retry, refresh, and network-error states

## Technology

- Flutter and Dart
- Open-Meteo Forecast and Geocoding APIs (no API key)
- `http`, `geolocator`, `shared_preferences`, `provider`, and `intl`

Open-Meteo's free service is intended for non-commercial use. Review its current terms before shipping a commercial product.

## Requirements

- Flutter SDK 3.27 or newer (Dart 3.3+)
- Android Studio or Xcode for the platform you want to run
- A network connection for forecast and city-search data

The repository contains the Flutter application source and location permission entries. The Android/iOS build wrappers are generated by Flutter so they match the SDK and local toolchain installed on your machine.

## Setup and launch

1. Install Flutter and confirm the SDK is available:

   ```sh
   flutter doctor
   ```

2. From the repository root, generate the native host projects. Flutter will add its standard Android and iOS runner files around the application source:

   ```sh
   flutter create --project-name flexiweather --platforms android,ios .
   ```

   If Flutter replaces either permission file during project generation, re-apply the location entries documented in [Location permissions](#location-permissions).

3. Fetch packages and start the app on a connected device or simulator:

   ```sh
   flutter pub get
   flutter run
   ```

4. To launch on a specific target, list available devices and pass its identifier:

   ```sh
   flutter devices
   flutter run -d <device-id>
   ```

The first launch loads San Francisco as a sample city. Search for any city or use the location button to load nearby weather. Location access is only requested when that button is used.

## Location permissions

The Android manifest at `android/app/src/main/AndroidManifest.xml` declares internet access and coarse/fine location permissions. The iOS `Info.plist` includes `NSLocationWhenInUseUsageDescription`. Keep the purpose text visible and specific if you customize the native runner.

## Project structure

```text
lib/
  main.dart                         App entry point and theme setup
  models/weather.dart               Typed weather data and unit conversion
  services/open_meteo_service.dart  Open-Meteo HTTP client
  state/weather_controller.dart     App state and persisted preferences
  ui/                               Weather screen, theme, and background
  ui/widgets/                       Forecast rows and city search sheet
test/
  weather_test.dart                 Parsing, weather codes, and temperature tests
```

## Verification

Run the project's standard checks after installing Flutter:

```sh
flutter pub get

flutter analyze
flutter test
```

## Data and privacy

Weather requests send the selected place's coordinates to Open-Meteo. Location is requested only after the user taps the location control; the app does not store a location history. Temperature units, the selected place, and favorite places are stored locally with SharedPreferences.
